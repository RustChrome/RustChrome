# RustChrome 0.2.2

Pre-release. Beta software, not a stable browser.

Patch release: the GTK shell finally has tests, and one of its longest functions was
split. No user-visible behaviour was meant to change — and that is exactly what the
tests are for.

## The GTK shell now has tests

`src/main.rs` had zero. It now has four, all in `shell_tests`:

* **The stylesheet still styles the controls we ship** — a selector disappearing
  means a control silently loses its styling.
* **The embedded GTK CSS parses** — under a display server. CI runs the suite under
  `xvfb-run`, so it executes for real; without a display it logs a skip instead of
  failing, because a missing display is not a bug in the browser.
* **The shell's preference names map to the typed fields** — `"dark"` is the UI's
  name, `"theme"` is the store's. That hand-written mapping is what destroyed settings in 0.2.0.
* **Writing one setting leaves the others alone** — the regression test for the
  0.2.1 data-loss bug, this time from the shell's side.

## `new_tab` split

`new_tab` was 251 lines: widget construction, webview configuration and event
wiring in one function. The 42-line webview configuration block is now
`App::create_view()`, which is the part that carries the privacy settings and is
therefore worth reading on its own.

The rest of the split — `build` (203 lines), `show_menu` (202), `on_ui_message`
(197) — is not in this release. It is still on the list, one function per commit.

## Everything from 0.2.1

The preference data-loss fix, counted bridge and layout failures, documented unsafe
contracts, `docs/ARCHITECTURE.md`, `docs/SECURITY-REVIEW.md`,
`docs/PERFORMANCE.md`, `docs/RELEASE.md`, and the claim-by-claim privacy table.

## Still true

Known bugs and everything untested are in `docs/QA.md`. Linux ignores per-site
permission rules and has no download manager or settings surface. No ad blocker, no
password manager, no macOS, no Android. Not anonymity.
