# RustChrome 0.2.3

**Many themes.** One shared palette, rendered by both shells.

## Themes

Six curated themes, remembered between sessions on Linux and Windows:

| Theme | Base |
|---|---|
| Light | default light (unchanged from 0.2.2) |
| Dark | default dark (unchanged from 0.2.2) |
| Graphite | neutral cool graphite, dark |
| Sepia | warm paper, light |
| Midnight | deep blue, dark |
| Nord | Nordic snow-and-storm palette, dark |

The two defaults reproduce the 0.2.2 colours slot-for-slot, so upgrading does
not restyle anyone.

### How it works

The colours live once, in `rc-core/src/themes.rs` — a semantic `Palette` (window,
chrome, surfaces, text, accent, hairlines, new-tab page). Each shell renders it
in its own substrate:

* **Linux** — one theme-agnostic GTK stylesheet over `@define-color rc_*` names;
  switching a theme reloads the palette block, and the ⋯ menu → *Themes* shows
  the full picker. The toolbar theme button cycles.
* **Windows** — the shell injects every theme into `chrome.html` at startup as
  `html[data-theme="…"]` blocks; the page flips by setting `data-theme` from the
  persisted id. The hardcoded `html.dark` block and `.dark` toast rule are gone.

The new-tab and error pages pull their colours from the same palette on both
platforms.

## Fixes in this release

* `rc-core` theme store now accepts any registered theme id (was hardcoded to
  `light`/`dark`) and repairs unknown values to the default on load.
* Removed the dead `save_dark` path and the `.dark` style-class plumbing on
  Linux; darkness is now derived from the theme registry, one source of truth.
* The privacy/settings row shows the real theme id instead of a
  "light"/"dark" guess.
* Docs corrected: `ARCHITECTURE.md` test count, README theme description.

## Verification

* `cargo test -p rc-core`: **45 passed** (themes palette integrity, accent
  contrast, historic-colour preservation, Windows chrome variable mapping).
* `cargo clippy -p rc-core --all-targets`: clean, no warnings.
* `cargo fmt --all`: clean.
* The GTK stylesheet parses for every theme under `xvfb-run` (test present;
  real-runner CI verifies).

## Known limitations (unchanged, disclosed)

* Windows and the full Linux shell build are verified on the real OS runners in
  CI, not in this session's sandbox (the sandbox lacks `webkit2gtk-4.0`).
* Themes restyle the browser chrome and the new-tab/error pages; web *content*
  is only affected by the existing "Force dark pages" option.
* Two light themes (Light, Sepia) and four dark — deliberately few; adding skins
  is a one-block change in `themes.rs` plus a test.

## Not in this release

* No per-site permission-rule enforcement on Linux (still stored, still not
  enforced there) — tracked in `TECHNICAL_DEBT.md`.
* No interactive GUI test harness — remains the largest testing gap.
* No external-protocol policy on Linux.
* Memory and Windows-startup reduction are still open measurement work.
