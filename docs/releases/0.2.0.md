# RustChrome 0.2.0 — first public beta

A small, privacy-first browser in Rust. Linux (GTK3 + WebKitGTK 4.1) and Windows
(Win32 + WebView2). MIT licensed. No accounts, no telemetry, no sync server, no
history database.

**This is a beta.** It browses, and it has holes. Read the known issues before
you install it, and please report what breaks.

Each archive has a `.sha256` file next to it. Verify before running:

```bash
sha256sum -c rustchrome-0.2.0-x86_64-linux.tar.gz.sha256
```

```powershell
(Get-FileHash .\rustchrome-0.2.0-x86_64-windows.zip -Algorithm SHA256).Hash.ToLower()
# compare with the first field of the .sha256 file
```

## Install

**Linux**

```bash
tar xzf rustchrome-0.2.0-x86_64-linux.tar.gz
cd rustchrome-0.2.0-x86_64-linux
./rustchrome
```

Debian/Ubuntu: `sudo apt install libgtk-3-0 libwebkit2gtk-4.1-0`
Arch: `sudo pacman -S gtk3 webkit2gtk-4.1`

**Windows** — unzip anywhere, run `rustchrome.exe`. Nothing is installed, nothing
is written to the registry. The build links a static C runtime, so no Visual C++
redistributable is needed.

## What is new since 0.1.0

**Windows.** There is now a Windows browser, not a mockup: native Win32 window,
WebView2 rendering, tabs with titles, back/forward/reload, omnibox, bookmarks bar,
downloads with progress and cancel, find in page, zoom, light and dark themes,
menus, and a portable ZIP that runs without an installer.

**Privacy, rebuilt honestly.** The 0.1.0 build claimed a fixed Firefox user agent
and "Tor-style" fingerprinting. WebKitGTK is not Firefox; a browser that lies
about its engine is a fingerprint of its own, and deterministic canvas noise is a
stable identifier. Both are gone:

* The user agent now matches the rendering engine.
* Canvas reads are salted with a **per-session** seed: stable while a session
  lasts, different on every launch, so the salt cannot recognise you next time.
* WebGL and WebRTC are neutralised in **Strict mode** (opt-in), coerced rather
  than removed by default so ordinary sites keep working.
* Third-party cookies off, ITP on (Linux), tracking prevention on (Windows),
  DNS prefetch and hyperlink auditing off, InPrivate tabs on Windows, an
  ephemeral WebKit context on Linux.
* A privacy dashboard on both platforms shows what is actually on, and what it
  does not do.

This makes you one of many. It does **not** hide your IP address, and it is not
Tor.

**Everyday features.** Import bookmarks from Chrome or Firefox (Windows detects
the installed Chrome profile), export to HTML, restore tabs after a crash,
Private or Standard session, Ctrl+Shift+A tab search, recently closed tabs,
custom search engines, per-site permission rules (Windows), cancellable
downloads.

**Testing that can fail.** Every push now runs on real Linux and Windows runners:
`cargo fmt --check`, `clippy -D warnings`, `cargo test`, release build,
`cargo audit`, a two-session anti-fingerprinting probe (18 invariants), a
memory/idle-CPU/startup measurement, and a compatibility run against four real
websites.

## Known issues

Documented in `docs/QA.md`, summarised:

* Linux ignores per-site permission rules and has no download manager.
* Linux has no settings UI for session mode, search engines or site rules.
* Windows private mode is InPrivate tabs, not an ephemeral profile.
* Crash recovery restores tabs without asking.
* Bookmarks are flat — no folders.
* No GUI interaction is covered by tests; no accessibility, certificate, soak or
  GPU testing.
* Measured on CI hardware, software rendering: Windows ~306–313 MB and ~7.8 s
  startup, Linux ~474 MB and ~1.9 s. Those are not lightweight numbers yet.

Not present at all: ad or tracker blocking, password manager, extensions beyond
userscripts, sync, macOS, Android.
